# AviUtl 操作体验目标

本文档定义 Freya NLE 应如何让已经熟悉 AviUtl 1.10 与 ExEdit 0.92 的用户感到顺手，同时仍然表现得像一款现代视频编辑器。它是产品和贡献指南，而非二进制兼容性的承诺。

Freya NLE 不会直接加载 AviUtl 或 ExEdit 插件。兼容目标在于编辑模型：时间线习惯、对象设置、参数编辑、关键帧操作、预览控制和项目流程，都应足够熟悉，让有经验的 AviUtl 用户能快速上手。

## 产品原则

Freya NLE 应当保留 AviUtl 中让精确、基于对象的编辑变得高效的部分，并替换那些使现代制作变得困难的部分。

当熟悉度能保护肌肉记忆时，优先保留熟悉度：

- 基于图层的对象放置，时间横向推进、图层纵向堆叠。
- 以对象为中心的编辑，时间线上的每个项目都拥有自己的时长、图层、参数、滤镜和运动。
- 参数支持直接数值输入，同时配有滑块和可视化控件。
- 中点/关键帧式动画编辑，带有显式插值。
- 紧凑的编辑窗口，优先考虑重复的生产工作而非营销式展示。

当现代化能消除结构性限制时，优先现代化：

- 在 Linux、Windows、macOS 上跨平台运行。
- 64 位内存、GPU 加速、感知硬件的解码/编码以及流畅的预览播放。
- 非破坏性编辑、可靠的撤销/重做、易于自动保存的项目数据以及抗崩溃的设置。
- 支持 Unicode 的路径、高 DPI 界面、本地化、无障碍和可预测的键盘行为。
- 通过包、Lua 插件、QML、GLSL 和权限控制提供安全的扩展点。

## 非目标

以下内容刻意排除在兼容目标之外：

- 与 AviUtl、ExEdit 或它们的原生插件 ABI 的二进制兼容性。
- 完美复刻每一个历史窗口大小、颜色、菜单标签或未记录的行为。
- 保留 32 位内存、单线程渲染或仅限 Windows 的 API 所导致的限制。
- 当不熟悉的现代特性能改善安全、性能或项目可移植性时，将其视为回归。

## 必需熟悉领域

### 项目启动与窗口

用户应当能够在无需学习新心智模型的情况下，从项目分辨率、帧率和时长开始。预览、时间线、对象设置、系统设置、项目设置和导出界面应保持足够独立以匹配 AviUtl 式的工作方式，但如果它们被隐藏或移动，应当能从菜单和快捷键中找回。

- 新建项目在开始编辑前就提供宽、高、帧率和场景默认值。
- 主预览和时间线可以通过键盘显示、隐藏和重新聚焦。
- 关闭或退出时会保护多个打开的项目标签中的未保存工作。
- 窗口状态应可持久化，但损坏的布局必须可重置。

### 时间线编辑

时间线是兼容目标的核心。用户应将图层、对象、拖拽放置、裁剪、分割、吸附、选择和中键创建视为类似 AviUtl 的操作。

- 时间首先以帧表示；时间码可以作为补充，但不应掩盖逐帧精确的工作。
- 图层是稳定的编辑轨道。锁定、可见性和图层专属行为不得意外改写对象时序。
- 拖动对象应保留时长和图层意图，除非用户显式裁剪、吸附、分组或执行批量操作。
- 多选行为在移动、删除、复制、剪切、粘贴、分割和属性检查时应可预测。
- 吸附应可见、可覆盖，并可针对每个场景或项目配置。
- 播放头和滑条/编辑目标应有清晰规则，使菜单命令在预期的帧和图层处创建或粘贴。参见[时间线编辑目标规则](./timeline-edit-targets)。
- 大型时间线必须保持可滚动、可缩放，而不强迫用户改变编辑方式。

### 对象、效果与滤镜

Freya NLE 应保留 AviUtl 用对象搭建场景并在其上叠加效果或滤镜的习惯。现代系统内部可能使用 JSON、QML、GLSL 和包，但用户应体验到可搜索的对象/效果目录，并具有一致的参数编辑。

- 内置对象覆盖常见的 AviUtl 式编辑构件：媒体、文本、图形、场景引用、音频、摄像机/控制对象和实用对象。
- 效果和转场可按本地化名称和类别搜索。
- 每个对象或效果都提供稳定的默认值、紧凑的参数界面和可重置的值。
- 效果顺序可见且可编辑。
- 禁用的效果保留在堆栈中，且不改变渲染输出。
- 第三方包安装后应看起来和行为都像内置条目，同时仍显示来源、版本和权限。

### 参数与关键帧编辑

AviUtl 用户期望数值精度和快速的动画控制。Freya NLE 应在保留这种精度的同时，增加更清晰的插值、校验和预览反馈。

- 数值参数支持直接输入、步进控件、在适用时提供滑块，以及在相关场景下提供单位。
- 颜色、文件、枚举、布尔、文本和分组控件在内置效果与包提供的效果之间使用一致的控件。
- 带有关键帧的参数应在对象设置界面中明显呈现其动画状态。
- 关键帧可以在当前编辑目标处添加、数值化编辑、删除，并在相邻帧处预览。
- 插值选择应显式、可检查，并且能在项目文件中序列化。
- 复制或复制对象必须保留其参数和关键帧数据。

### 预览与播放

预览必须足够即时，以满足日常编辑需要。如果全质量预览成本过高，编辑器应有意图地降级，而不是变得无响应。

- 当文本输入未获得焦点时，空格切换播放。
- 跳转、滑条和对象参数更改应以低延迟更新预览。
- 预览渲染不应阻塞基本的时间线交互。
- 音频播放、电平表和波形应与帧位置保持同步。
- 质量/性能设置应易于理解，无需用户了解渲染器内部原理。

### 导入、保存与导出

Freya NLE 应让现代媒体工作流比经典 AviUtl 更可靠，尤其是在 Unicode 路径、长项目、音频和编解码器方面。

- 拖放导入会校验文件 URL，并安全地拒绝不支持的协议。
- 项目文件保留场景、片段、图层状态、效果、关键帧、插件状态和包引用。
- 缺失媒体应提供足够的上下文以便重新链接或替换。
- 导出首先暴露实用预设，必要时提供高级编解码器控制。
- 可以提供硬件编码器，但软件回退必须始终清晰可用。
- 导出失败应指明失败阶段，并让部分输出处于可预测的状态。

### 快捷键与菜单

键盘习惯是 AviUtl 体验的一部分。Freya NLE 应让常用编辑命令保持快捷，同时允许现代的快捷键自定义。

- 核心命令具有默认快捷键，包括新建、打开、保存、另存为、导出、撤销、重做、播放、时间线/对象设置可见性、分割、复制、剪切、粘贴、删除和项目设置。
- 快捷键编辑会校验冲突并支持恢复默认值。
- 上下文菜单应暴露与键盘操作相同的命令词汇，让用户可以先发现命令再记忆快捷键。
- 文本输入框不得意外触发全局时间线命令。

## 现代编辑器要求

这些要求是让 AviUtl 式模型能在当前系统上存续的关键。

### 稳定性与数据安全

- 设置和项目保存应原子化或可恢复。
- 撤销/重做必须描述用户操作，而非实现事件。
- 后台解码、插件扫描、导出和预览工作不得与 UI 编辑产生数据竞争。
- 当内存压力不可避免时，长媒体和大型时间线应优雅失败。

### 性能

- 大型项目中时间线滚动、缩放和选择应保持交互。
- 长文件的音频解码应流式或分块进行。
- 帧缓存应有明确的限制和逐出行为。
- GPU 效果应有可预测的回退或清晰的"不支持"状态提示。
- 性能回归应通过可重复的场景来衡量，而不仅仅是主观的预览检查。

### 可扩展性

- 内置效果与包提供的效果应共享同一套元数据模型。
- 插件权限应默认遵循最小权限原则。
- 包安装应在部署前校验 ID、路径、版本和归档。
- 扩展 API 应优先使用稳定、有文档记录的操作，而非直接访问内部 UI 对象。

### 本地化与无障碍

- 面向用户的字符串应可本地化。
- 数值输入在不同区域设置下应保持无歧义。
- 高 DPI 显示不应改变编辑精度。
- 重要状态不应仅依靠颜色传达。
- 键盘导航应覆盖重复的编辑工作流，而不只是对话框。
