# 发布检查清单

在创建 AviQtl-Plus 发布标签之前，请使用此清单。只有当被标记的提交在不依赖先前构建目录的情况下通过以下检查时，发布才是有效的。

## 版本

- 更新 `CMakeLists.txt` 中的 `project(AviQtl VERSION ...)`。
- 在 `CHANGELOG.md` 中添加发布章节和日期。
- 使用与 `v<项目版本>` 完全一致的标签名称。发布工作流会拒绝不匹配的标签。
- 确认打包后的"关于"对话框显示相同的版本。`BUILD.py` 默认使用 CMake 项目版本；`--version` 只是显式覆盖。

## 干净构建与测试

在每个支持的平台上，从新建的构建目录运行 Release 构建，然后运行所有 CTest 测试并打印失败信息：

```text
ctest --test-dir <干净构建目录> --output-on-failure
```

必需平台：

- Arch Linux 容器/运行器
- macOS 运行器
- Windows MSVC 运行器（Windows 默认构建环境）

MSYS2 是显式选择的替代方案，不是 Rust 默认的 Windows 构建环境。

不要将被跳过的分析工具或测试视为通过的覆盖。任何在未输出 Qt Test 结果的情况下退出的测试进程都应作为启动或运行时失败进行调查。

## 质量与打包

- 在包含全部已配置分析工具的环境中运行 `python check.py --full`。
- 确认发布归档包含可执行文件、Qt/QML 运行时资源、翻译、内置效果/对象/转场、效果包，以及所需的 Carla/FFmpeg 运行时库。
- 启动打包后的应用，创建项目，保存并重新打开，渲染一个短视频，并在编辑器外验证输出。
- 在没有构建工具链的机器或干净的虚拟机上验证安装和启动。

## 发布

- 确认发布提交的所有必需 GitHub Actions 任务均为绿色。
- 仅在以上检查通过后创建版本标签。
- 在宣布发布之前，下载并对标签工作流生成的构件进行冒烟测试。
