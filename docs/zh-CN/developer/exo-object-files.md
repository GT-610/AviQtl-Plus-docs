# AviUtl 物件文件（`.exo`）

AviUtl 扩展编辑可以把选中的物件保存为扩展名为 `.exo` 的**物件文件**：一个小的文本文件，保存物件的位置、图层号、每个物件的滤镜栈以及全部参数值。AviQtl-Plus 读写这一格式，因此既能把已有的 AviUtl 素材引入项目，也能把完成的场景交还给 AviUtl。

- **文件 → 导入 AviUtl 物件文件…** 把文件中的物件追加到当前场景已有物件之后，整体作为一次可撤销的编辑。
- **把 `.exo` 文件拖到时间线上**会以文件最早物件为基准放到指针位置，与 AviUtl 行为一致。
- **文件 → 导出 AviUtl 物件文件…** 把当前场景的物件写出。

这两个命令只处理物件文件本身。它们不会执行扩展编辑脚本，也不会让 AviQtl-Plus 加载 AviUtl 插件。

## 格式内容

```text
[exedit]
width=1280
height=720
rate=30
length=120
...
[0]              ; 一个物件：起始帧、结束帧、图层均为 1 起始
start=11
end=40
layer=3
[0.0]            ; 物件本体：文本、图形、图像、视频、音频……
_name=文本
text=604f7d59
[0.1]            ; 按栈顺序排列的滤镜
_name=模糊
范围=8
[0.2]            ; 标准描画（变换）始终在最后
_name=标准属性
X=100.0
...
```

键不加引号，值本身可以包含 `=`，因此每行只按第一个 `=` 切分。帧和图层在磁盘上是 1 起始，所以 `start=11` 的物件在 AviQtl-Plus 中从第 10 帧开始。会变化的数值参数保存为 `起始值,结束值,变化方式,参数`，例如 `X=100.0,300.0,15@easing_普通@uf_easing,16`。

## 文本编码

AviUtl 用系统 ANSI 代码页写字符串，而不是 Unicode。汉化包因此产生 GBK，原版日文环境产生 Shift-JIS，手工编辑的文件常常是 UTF-8。导入器按文件检测编码并记住它，所以导入后再导出的文件仍能被同一个 AviUtl 正常读取。

## 会被翻译的内容

| 扩展编辑物件或滤镜 | AviQtl-Plus 结果 |
| --- | --- |
| 文本 / テキスト | 文本物件：文本、字体、字号、颜色、描边色、粗体、斜体、字间距、行间距、对齐方式 |
| 图像 / 画像、视频 / 動画、音频 / 音声 | 图像、视频或音频物件，引用路径取自物件的二进制数据 |
| 标准属性 / 標準描画（描画） | 变换效果：位置、缩放、不透明度、Z 轴旋转、合成模式 |
| 模糊、边缘模糊、马赛克、单色化、裁剪遮罩、色调修正、淡化、锐化、振动、镜像、极坐标变换、光栅、方向模糊、放射模糊、镜头模糊、发光、描边、阴影、色度键、亮度键、渐变、图像拼贴 | 对应的内置效果，参数换算为本项目单位 |

带动画的数值参数会转成两点关键帧：第 0 帧取起始值，物件最后一帧取结束值。

## 会保留但不参与渲染的内容

其余内容——扩展编辑脚本物件（自定义物件、动画效果、カスタムオブジェクト）、图形物件、摄像机、组控制、音频滤镜，以及任何没有确认对应关系的效果——都会作为**禁用的占位项**导入：保留名称、脚本标识、脚本参数块、数值与勾选值以及二进制数据。它会出现在效果栈中，不影响画面，并在导出时原样写回。

导入器不做猜测。参数含义未经确认的效果如果强行转换，会静默改变画面，而错误的画面远比效果栈里一条禁用项更难被发现。

## 需要了解的局限

- **不执行脚本。** 扩展编辑脚本是带自有 API 的 Lua 程序，执行它们是另一项功能，因此脚本产生的效果目前无法复现。
- **不转换图形物件。** 扩展编辑的図形有自己的几何与基于文件的图形类型，目前没有忠实映射。
- **变化方式是近似值。** 数值参数的变化方式保存为缓动脚本内的标签，而非曲线标识。含义明确对应线性、加速、减速或加减速的标签会被转换，其余按线性处理，并把原始文本保留在关键帧上。
- **素材路径靠启发式恢复。** 扩展编辑把引用的文件存放在每个物件的二进制数据里，布局随物件类型不同。导入器在该数据中搜索以常见媒体扩展名结尾、以 NUL 终止的路径。找不到的文件会由**文件 → 管理丢失的素材**报告，而不是被静默丢弃。
- **导出会重新序列化数值。** 数值按项目当前状态写出，因此导出的文件使用规范化的数字形式（AviUtl 写 `100.00` 之处本软件写 `100.0`），文本缓冲区也不再保留固定长度的 NUL 填充。AviUtl 对两者的读取结果相同。
- **帧与图层偏移目前固定为零。** 导入的物件保持相对布局，这与 AviUtl 自身"追加到当前数据末尾"的行为一致。
