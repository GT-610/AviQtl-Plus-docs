# AviUtl 物件文件（`.exo`）

AviUtl 扩展编辑可以把选中的物件保存为扩展名为 `.exo` 的**物件文件**：一个小的文本文件，保存物件的位置、图层号、每个物件的滤镜栈以及全部参数值。AviQtl-Plus **读取**这一格式，因此能把已有的 AviUtl 素材引入项目。

这是**单向**的**兼容**路径。扩展编辑的物件模型比本项目窄，因此导入只翻译能拿出依据的部分，其余变成禁用的占位项，而不是靠猜。反向写回物件文件意味着凡本软件能表达、扩展编辑装不下的内容都得丢弃，所以 AviQtl-Plus 不写物件文件：在项目之间搬运工作请用[片段文件](./fragment-files)。

- **文件 → 导入 AviUtl 物件文件（兼容）…** 把文件中的物件追加到当前场景已有物件之后，整体作为一次可撤销的编辑。
- **把 `.exo` 文件拖到时间线上**会以文件最早物件为基准放到指针位置，与 AviUtl 行为一致。
- **文件 → 从 AviUtl 物件文件新建项目…** 会用文件中的分辨率、帧率、音频采样率和长度建立项目，再把物件导入第一个场景，对应 AviUtl 的"从物件文件新建"。

这些命令只处理物件文件本身。它们不会执行扩展编辑脚本，也不会让 AviQtl-Plus 加载 AviUtl 插件。

## 格式内容

```text
[exedit]
width=1280
height=720
rate=30
length=120
...
[0]              ; 一个物件：起始帧、结束帧、图层均为 1 起始
start=11
end=40
layer=3
[0.0]            ; 物件本体：文本、图形、图像、视频、音频……
_name=文本
text=604f7d59
[0.1]            ; 按栈顺序排列的滤镜
_name=模糊
范围=8
[0.2]            ; 标准描画（变换）始终在最后
_name=标准属性
X=100.0
...
```

键不加引号，值本身可以包含 `=`，因此每行只按第一个 `=` 切分。帧和图层在磁盘上是 1 起始，所以 `start=11` 的物件在 AviQtl-Plus 中从第 10 帧开始。会变化的数值参数保存为 `起始值,结束值,变化方式,参数`，例如 `X=100.0,300.0,15@easing_普通@uf_easing,16`。

## 文本编码

AviUtl 用系统 ANSI 代码页写字符串，而不是 Unicode。汉化包因此产生 GBK，原版日文环境产生 Shift-JIS，手工编辑的文件常常是 UTF-8。导入器按文件检测编码，因此无论来自哪个包的文件都能正确读取，不必询问用户是哪一个。

## 会被翻译的内容

| 扩展编辑物件或滤镜 | AviQtl-Plus 结果 |
| --- | --- |
| 文本 / テキスト | 文本物件：文本、字体、字号、颜色、描边色、粗体、斜体、字间距、行间距、对齐方式 |
| 图像 / 画像、视频 / 動画、音频 / 音声 | 图像、视频或音频物件，引用路径取自物件的二进制数据 |
| 图形 / 図形 | 图形物件：内置图形类型转为正多边形（填充矩形、三角形、五边形、六边形、十顶点星形；圆形用密集多边形近似），`大小` 作为绘制半径，`长宽比` 转为纵横比，`线宽` 转为描边 |
| 标准属性 / 標準描画（描画） | 变换效果：位置、缩放、不透明度、Z 轴旋转、合成模式 |
| 模糊、边缘模糊、马赛克、单色化、裁剪遮罩、斜向裁剪、色调修正、淡化、锐化、振动、镜像、极坐标变换、光栅、方向模糊、放射模糊、镜头模糊、发光、辉光、扩散光、提取边缘、噪波、描边、阴影、色度键、亮度键、渐变、图像拼贴 | 对应的内置效果，参数换算为本项目单位 |

带动画的数值参数会转成两点关键帧：第 0 帧取起始值，物件最后一帧取结束值。

### 滤镜名是本地化的

AviUtl 通过本地化的 `_name` 查找滤镜，所以汉化包写 `标准属性`，而原版写 `標準描画`。导入器接受所有已知拼写，把它们当作同一个滤镜处理。

## 如何新增一项翻译

映射是数据而非代码。只有名称与参数语义都确证时才翻译，因此新增一条记录需要分别取证。

1. 在 ExEdit 自身的滤镜表里找到它：本地化显示名、每个数值参数的名称与默认值、每个勾选项名称，以及标志位；`exo_mapping.rs` 只镜像导入器需要的部分。
2. 把参数名与目录效果自身的参数对照，并用默认值检验缩放：ExEdit 里存 `1000`、本项目里是 `100` 的百分比意味着缩放 `0.1`。默认值不一致并不自动等于错误——两个效果的默认模糊半径本来就可以不同——但它意味着缩放需要另找依据，通常是同一张表里同一量在相同缩放下的出现。若找不到任何依据，该滤镜保持占位项。
3. 添加 `FilterMapping`（或 `ObjectMapping` / 图形类型），同时列出中文、日文、英文拼写——汉化包、原版和各种工具的命名各不相同。
4. 用包含该滤镜的文件做导入测试：把 `AVIUTL_SAMPLES` 指向 AviUtl 整合包，运行 `cargo test -p aviqtl-app --test exo_samples -- --ignored`。测试会导入整合包里每个文件，检查每个物件都变成带有文件给定位置的片段，且被保留的内容没有丢失，因此某个滤镜停止翻译会在这里暴露，而不是在用户的项目里。

本项目新建的物件在没有来源拼写时使用第一个别名，因此把汉化包使用的名字放在最前面。

## 会保留但不参与渲染的内容

其余内容——扩展编辑脚本物件（自定义物件、动画效果、カスタムオブジェクト）、图形物件、摄像机、组控制、音频滤镜，以及任何没有确认对应关系的效果——都会作为**禁用的占位项**导入：保留名称、脚本标识、脚本参数块、数值与勾选值以及二进制数据。它会出现在效果栈中，但不影响画面。

占位项是一份记录，而不是一个可用的效果：它的职责是让文件说过的话在项目里保持可见、保持完整，以便之后继续使用这些素材——保存为片段，或交给将来真正执行扩展编辑脚本的功能。

占位项是可检视的：选中它会显示导入器保留的全部内容的只读行，包括脚本标识和每个保留下来的键。这些行标记为"不支持"而不是可编辑，因为这个效果目前不会运行。

导入留下占位项时，AviQtl-Plus 会弹出报告，逐条列出被保留的物件或滤镜。若该效果由脚本提供，报告会写明脚本名——那正是用户要让物件生效所需安装的文件。没有任何保留时不会打扰用户，因此这个对话框只在画面可能与 AviUtl 不同时出现。

导入器不做猜测。参数含义未经确认的效果如果强行转换，会静默改变画面，而错误的画面远比效果栈里一条禁用项更难被发现。

每个物件还带有路由标志：`group` 把它绑定到组控制、`clipping` 让它被上层物件裁剪、`audio` 标记它是音频物件，`chain` 与 `camera` 则改变它的作用对象。本项目没有对应字段，因此这些标志保存在片段的附加字段里，而不是被丢弃。

扩展编辑还会自行追加一些簿记性质的滤镜——上层物件缓存和帧缓冲抓取。它们不承载创作意图，AviUtl 也不把它们显示为可编辑项，因此直接跳过：放进效果栈会显示 AviUtl 从未展示过的滤镜，而它们也没有渲染需要的数据。

## 需要了解的局限

- **不执行脚本。** 扩展编辑脚本是带自有 API 的 Lua 程序，执行它们是另一项功能，因此脚本产生的效果目前无法复现。
- **变化方式是近似值。** 数值参数的变化方式保存为缓动脚本内的标签，而非曲线标识。含义明确对应线性、加速、减速或加减速的标签会被转换，其余按线性处理，并把原始文本保留在关键帧上。
- **不转换位图图形。** 図形 还可以引用 `figure` 目录下的单色 PNG，这类物件会作为占位项保留，只有内置类型会被转换。
- **文本对齐只保留、不翻译。** 扩展编辑把 `align` 存成打包设置，其编码尚未确认，因此导入的值原样保留，本软件的对齐参数保持默认。
- **素材数据块只用来看路径。** 扩展编辑把引用的文件存放在每个物件的二进制数据里，布局随物件类型不同。导入器在该数据中搜索以常见媒体扩展名结尾、以 NUL 终止的路径，并把数据块一起保留；片段实际使用的是其中的路径。找不到的文件会由**文件 → 管理丢失的素材**报告，而不是被静默丢弃。
- **导入会扩展场景。** 如果文件超出场景末尾，场景会作为同一次可撤销编辑被延长，避免导入内容的尾部被时间线末端挡住。导入不会缩短已经更长的场景。
- **导入会前移而不是重叠。** 当文件会落在已有物件占用的帧上时，整块内容前移，
  报告会说明移动了多少帧。扩展编辑拒绝载入到已被占用的位置，直接叠上去会让两个物件
  共用同一图层同一帧。
